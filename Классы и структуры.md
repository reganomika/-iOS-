## Q1 · Инициализаторы в структуре &nbsp;🟢
🗣 *Расскажи про инициализацию структур: что даётся по умолчанию и что это отключает.*

🎯 **Ядро.** Нет своих init → компилятор даёт **memberwise** `init(...)` и `init()` (если у всех полей есть дефолты). Свои init тоже можно (несколько, `init?`, `throws`), но любой свой init **в теле** структуры отключает memberwise-синтез.

<details><summary>🔍 Детали: почему · ловушка · 🧠 якорь · вслух</summary>

🔑 **Почему.** Пока не присвоены все stored-поля, к `self` обращаться нельзя (`let` — ровно один раз). Так гарантируется «нет частично собранного значения».

⚠️ **Ловушка.** Объявил свой init в теле — memberwise пропал. Хочешь оба → выноси свой init в `extension`.

🧠 **Якорь.** Memberwise — как заводская гарантия: действует, пока ты сам не вскрыл корпус (не написал свой init в теле).

💬 **Вслух.** «Memberwise по умолчанию, но свой init убивает синтез; чтобы сохранить оба — выношу init в extension.»

⚡ **А если спросят:** «Нужен и свой `init`, и memberwise — как?» → Свой init в `extension`, тело структуры остаётся «нетронутым».

</details>

<details><summary>📖 Глубже + код</summary>

**Memberwise** — параметры и доступность зависят от уровней доступа stored-полей (`private` → недоступен извне). **Default `init()`** — когда у всех полей есть дефолты/`nil`. Невозможное состояние → `init?` или `init throws`.

```swift
struct User {
    let id: String
    var name: String = "Anonymous"

    init(id: String, name: String? = nil) {   // свой init → memberwise пропал
        self.id = id
        self.name = name ?? "Anonymous"
    }

    init?(rawID: String) {                      // failable; name возьмёт дефолт
        guard !rawID.isEmpty else { return nil }
        self.id = rawID
    }
}
```

*Источник:* Swift Language Guide — Initialization.

</details>

## Q2 · Copy-on-write (CoW) &nbsp;🟢
🗣 *Расскажи, что знаешь о copy-on-write — и когда буфер реально копируется.*

🎯 **Ядро.** Копии value-типа делят один heap-буфер, пока его не мутируют; реальная копия буфера — при первой мутации **не-уникального** буфера (проверка `isKnownUniquelyReferenced`). Есть у `Array`, `Dictionary`, `Set`, `String`, `Data`.

<details><summary>🔍 Детали: почему · ловушка · 🧠 якорь · вслух</summary>

🔑 **Почему.** Копировать дорого, а большинство копий только читают — затраты откладываются до момента, когда правда нужны.

⚠️ **Ловушка.** CoW ≠ thread-safe: две мутации одного значения из разных потоков = data race. Первая мутация после шаринга может быть дорогой.

🧠 **Якорь.** Общий Google-Док: пока все читают — документ один на всех; как только кто-то печатает — ему втихаря делают личную копию.

💬 **Вслух.** «Storage общий до первой мутации; тогда, если буфер не уникален, делается копия — value semantics сохранены.»

⚡ **А если спросят:** «Передал массив в функцию, она только читает — копия буфера была?» → Нет, пока нет мутации.

</details>

<details><summary>📖 Глубже + код</summary>

Кастомный CoW строят вокруг reference-хранилища:

```swift
final class Storage {
    var values: [Int]
    init(_ v: [Int]) { values = v }
    func copy() -> Storage { Storage(values) }
}

struct CoWBox {
    private var storage: Storage
    init(_ v: [Int]) { storage = Storage(v) }

    private mutating func ensureUnique() {
        if !isKnownUniquelyReferenced(&storage) { storage = storage.copy() }
    }
    mutating func append(_ x: Int) { ensureUnique(); storage.values.append(x) }
}
```

Копия бывает и по другим причинам (реаллокация при росте capacity). Layout `String`/`Array` зависит от версии Swift/ABI — объясняй принцип, не байты.

*Источники:* Swift stdlib (Array/String), `isKnownUniquelyReferenced`, WWDC по value semantics.

</details>

## Q3 · Что быстрее: структура или класс? &nbsp;🟠
🤔 *Что быстрее — структура или класс, и от чего это зависит?*

🎯 **Ядро.** Универсального ответа нет. Обычно `struct` быстрее (inline-хранение, cache locality, нет ARC, static dispatch); `class` платит за ARC + heap-аллокацию + indirection. Но большой часто копируемый value-тип может проигрывать классу.

<details><summary>🔍 Детали: почему · ловушка · 🧠 якорь · вслух</summary>

🔑 **Почему.** struct лежит подряд и копируется как байты; class — это аллокация в heap + retain/release на каждое присваивание/передачу/захват.

⚠️ **Ловушка.** Сравнивать «struct vs class» без сценария бессмысленно — надо уточнить операцию (создание/копирование/доступ/коллекции).

🧠 **Якорь.** Записку носишь в копиях; рояль не таскаешь — даёшь адрес, где он стоит. Маленькое → struct, большое и часто передаваемое → ссылка (class).

💬 **Вслух.** «Уточню сценарий. Обычно struct быстрее из-за локальности и отсутствия ARC, но большой часто копируемый тип может проигрывать классу. Финал — мерить в Instruments.»

⚡ **А если спросят:** «Когда class реально быстрее?» → Когда value-тип большой и его часто копируют/возвращают между слоями.

</details>

<details><summary>📖 Глубже + код</summary>

- **Локальность.** `Array<Struct>` хранит элементы подряд (меньше cache misses); `Array<Class>` — подряд только ссылки, объекты разбросаны по heap.
- **Копии.** Маленькие структуры — дёшево; большие — дорого при частой передаче. CoW спасает только типы, которые его реализуют.
- **ARC.** У класса retain/release; у struct ARC нет, но работает для reference-полей внутри.
- **Dispatch.** Value-типы чаще допускают static dispatch + inlining + specialization; классы — virtual (vtable), хотя `final` + WMO дают девиртуализацию.

*Источники:* WWDC по performance, Instruments (Time Profiler / Allocations).

</details>

## Q4 · Почему размер структуры должен быть известен заранее? &nbsp;🟠
🤔 *Почему компилятору нужен фиксированный размер структуры — и как тогда делать рекурсивные?*

🎯 **Ядро.** `struct` лежит **inline** (стек / внутри другого значения / в буфере массива), поэтому нужен фиксированный размер и layout — для аллокации, копирования и доступа к полям по offset (`base + offset`). Рекурсия — только через индирекцию (ссылка / `indirect`).

<details><summary>🔍 Детали: почему · ловушка · 🧠 якорь · вслух</summary>

🔑 **Почему.** Кадр стека нарезается заранее; доступ к полю = `base + offset` — без известного размера это невозможно.

⚠️ **Ловушка.** Структура со stored-полем самого себя = бесконечный размер (не компилируется).

🧠 **Якорь.** Полка на стеке нарезается заранее — габариты надо знать. Структура внутри себя = матрёшка без дна (∞); спасает «адрес склада» — ссылка на heap.

💬 **Вслух.** «Value-тип лежит inline, поэтому размер должен быть определим. Рекурсию делаю через индирекцию: Box-ссылку или indirect enum.»

⚡ **А если спросят:** «Как сделать связный список на value-типах?» → Через ссылку (`Box<Node>?`) или `indirect enum`.

</details>

<details><summary>📖 Глубже + код</summary>

```swift
struct Node { var next: Node }          // ❌ бесконечный размер

final class Box<T> { var value: T; init(_ v: T) { value = v } }
struct Node2 { var next: Box<Node2>? }  // ✅ фиксированный размер (optional-ссылка)

indirect enum List<T> { case end; case node(T, List<T>) }  // ✅ через indirect
```

`Array`/`String`/`Data` логически переменного размера, но само значение фиксированного размера и держит ссылки/счётчики на heap-буфер. Generic: `Foo<Int>` и `Foo<String>` — разные размеры, но каждый фиксирован после специализации.

*Источники:* Swift Language Guide — Initialization, `indirect enum`.

</details>

## Q5 · Когда лучше класс, а когда структура? &nbsp;🟠
⚖️ *Когда берёшь class, а когда struct?*

🎯 **Ядро.** Критерий — **семантика**, не скорость. Нужна независимая копия → `struct` (value semantics). Нужна identity / разделяемое изменяемое состояние → `class` (или `actor`).

<details><summary>🔍 Детали: почему · ловушка · 🧠 якорь · вслух</summary>

🔑 **Почему.** struct = «значение» (две одинаковые копии неразличимы); class = «сущность» с identity (`===`), на которую все ссылаются и видят изменения.

⚠️ **Ловушка.** «struct = thread-safe» неверно (зависит от мутаций и reference-содержимого). А `class` «на всякий случай» → сайд-эффекты + retain cycles.

🧠 **Якорь.** Деньги против человека: 10₽ = 10₽, копия неважна (struct). А «тот самый Иван» — один, на него все ссылаются (class).

💬 **Вслух.** «Независимая копия — struct; общая идентичность и shared mutable state — class или actor.»

⚡ **А если спросят:** «Модель данных и сетевой сервис — что чем?» → Модель `struct`, сервис `class`; shared mutable → `actor`.

</details>

<details><summary>📖 Глубже + код</summary>

**`struct` когда:** значение, а не сущность (координаты, конфиг, результат); копия = независимый объект; иммутабельность для предсказуемости; хранение в коллекциях.

**`class` когда:** identity (`===`); shared mutable state видно всем держателям (кэш, репозиторий, плеер, модель с подписчиками); жизненный цикл и интеграция с Cocoa (`UIView`, `URLSessionTask`, KVO/`@objc`).

*Источники:* Swift Language Guide — Structures and Classes; Swift Concurrency (actors).

</details>

## Q6 · Работает ли ARC со структурами? &nbsp;🟠
🤔 *Работает ли ARC со структурами?*

🎯 **Ядро.** ARC считает ссылки только на **объекты классов** (heap) — у самой `struct` нет retain/release. Но если внутри есть `class`/замыкание, ARC работает для **этих полей** при копировании структуры.

<details><summary>🔍 Детали: почему · ловушка · 🧠 якорь · вслух</summary>

🔑 **Почему.** Value-тип живёт по scope и копируется целиком — считать ссылки не на что. А reference-поле внутри — это настоящая ссылка, её ARC ведёт.

⚠️ **Ловушка.** «struct = без ARC» верно только про саму обёртку. Выбор `struct` не выключает ARC, если внутри классы/замыкания.

🧠 **Якорь.** Struct — конверт без счётчика. ARC не считает конверты, только объекты-вложения внутри них.

💬 **Вслух.** «ARC не управляет самой структурой, но работает для её reference-полей.»

⚡ **А если спросят:** «`struct S { var onTap: () -> Void }` — есть работа ARC при копии S?» → Да, замыкание — reference (и потенциальный retain cycle).

</details>

<details><summary>📖 Глубже + код</summary>

```swift
final class C { deinit { print("deinit") } }
struct S { var obj: C }

do {
    var s = S(obj: C())
    let s2 = s        // value-копия копирует ссылку на C → ARC: +1 retain
    _ = s2
}                     // выход из scope → ARC освободит C, когда счётчик = 0
```

Где физически лежит struct (stack/heap/inline) — оптимизация компилятора, семантику не меняет.

*Источники:* Swift Language Guide — ARC; Instruments (Allocations).

</details>

## Q7 · Какой тип диспетчеризации у value-типов? &nbsp;🟠
🗣 *Какой dispatch у value-типов и когда появляется динамика?*

🎯 **Ядро.** По умолчанию value-типы используют **static (direct) dispatch** — компилятор знает реализацию, зовёт напрямую (+ шанс на inlining). Динамика (**witness table**) появляется при вызове через протокол (`any P` или generic).

<details><summary>🔍 Детали: почему · 🧠 якорь · вслух</summary>

🔑 **Почему.** У value-типа нет наследования → нечего разрешать в рантайме; протокол вводит уровень абстракции, который резолвится через таблицу.

🧠 **Якорь.** Знаешь номер — звонишь напрямую (static). Через протокол — сперва смотришь в справочник-таблицу (witness), потом звонишь.

💬 **Вслух.** «Value-типы в основном static dispatch; динамика — при вызовах через протоколы, там witness table.»

⚡ **А если спросят:** «Вызов метода struct через `any P` — какой dispatch?» → Witness table. (`vtable` — про классы, message dispatch — про `@objc dynamic`.)

</details>

<details><summary>📖 Глубже + код</summary>

```swift
struct Counter { var value = 0; mutating func inc() { value += 1 } }
var c = Counter(); c.inc()          // static/direct dispatch

protocol P { func f() }
struct S: P { func f() {} }
let p: any P = S(); p.f()           // witness table (existential)
```

Через generic с известным конкретным типом компилятор часто специализирует и «разворачивает» вызов в прямой — но механизм протокола это witness.

*Источники:* Swift ABI / witness tables, WWDC по generics.

</details>

## Q8 · Как работает `mutating` и когда он нужен? &nbsp;🟠
🗣 *Зачем value-типу `mutating` и почему классу он не нужен?*

🎯 **Ядро.** `mutating` нужен методам `struct`/`enum`, которые меняют `self` или его поля (без него value-тип «заморожен»). В протоколе фиксирует контракт «реализация может менять self». Классу не нужен — он меняется по ссылке.

<details><summary>🔍 Детали: почему · ловушка · 🧠 якорь · вслух</summary>

🔑 **Почему.** Value-тип в `let` иммутабелен — нужна явная пометка, что метод изменяет значение. У класса сам `self` (ссылка) не заменяется → пометка не требуется.

⚠️ **Ловушка.** `mutating` — про изменение value-типа, а **не** про многопоточность.

🧠 **Якорь.** `mutating` = табличка «вошёл в режим редактирования себя». Value-типу нужна; класс правит по ссылке — табличка не требуется.

💬 **Вслух.** «mutating отмечает методы, меняющие self; нужен в протоколе, чтобы struct/enum его реализовали. Класс выполняет тот же контракт без mutating.»

⚡ **А если спросят:** «Класс реализует протокол с `mutating func` — пишем `mutating`?» → Нет. Бонус: `mutating` позволяет `self = ...` целиком (часто в enum-машинах).

</details>

<details><summary>📖 Глубже + код</summary>

```swift
struct Counter {
    private(set) var value = 0
    mutating func inc() { value += 1 }   // без mutating — ошибка компиляции
}

enum State {
    case idle, loading, loaded(Int)
    mutating func setLoaded(_ v: Int) { self = .loaded(v) }   // переприсвоение self
}

protocol Resettable { mutating func reset() }
struct S: Resettable { var x = 10; mutating func reset() { x = 0 } }
final class C: Resettable { var x = 10; func reset() { x = 0 } } // без mutating
```

**Мутацией считается:** запись в stored property, вызов другого `mutating`, `inout`-доступ к `self`, переприсвоение `self`.

*Источники:* Swift Language Guide — Methods (Mutating), Protocols.

</details>

## Q9 · Stored vs computed properties и layout &nbsp;🟠
⚖️ *Чем stored-свойства отличаются от computed и как это влияет на память?*

🎯 **Ядро.** **Stored** хранит значение физически в экземпляре → влияет на `size`/`stride`/`alignment` (и на ABI). **Computed** — это геттер/сеттер (код, не данные) → размер экземпляра **не** меняет. `lazy` — это тоже stored.

<details><summary>🔍 Детали: почему · ловушка · 🧠 якорь · вслух</summary>

🔑 **Почему.** stored нужно где-то хранить; computed вычисляется при обращении из других данных — хранить нечего.

⚠️ **Ловушка.** Stored-поля влияют на **ABI**: добавил/переставил → сломал бинарную совместимость публичной библиотеки.

🧠 **Якорь.** Stored — товар на полке (занимает место). Computed — ценник, пересчитываемый по формуле (места не занимает).

💬 **Вслух.** «Stored — память экземпляра, влияет на size/stride и ABI; computed — функции, места не занимают; lazy — stored с отложенной инициализацией.»

⚡ **А если спросят:** «Добавил computed property — экземпляр стал больше?» → Нет, 0 байт (проверяется `MemoryLayout`).

</details>

<details><summary>📖 Глубже + код</summary>

```swift
struct Rect {
    var w, h: Double
    var area: Double { w * h }                    // computed read-only — 0 байт
    var side: Double { get { w } set { w = newValue; h = newValue } }
}

struct A { var x: Int }
struct B { var x: Int; var y: Int { x } }
MemoryLayout<A>.size   // 8 (64-bit)
MemoryLayout<B>.size   // тоже 8: computed не добавил хранения
```

Частый приём — computed API поверх stored backing (`_age` хранит, `age` валидирует в сеттере): размер определяет `_age`.

*Источники:* Swift Language Guide — Properties; Library Evolution (ABI); `MemoryLayout`.

</details>

## Q10 · Exclusivity enforcement (Law of Exclusivity) &nbsp;🔴
🗣 *Что такое exclusivity enforcement (закон эксклюзивности)?*

🎯 **Ядро.** Swift требует **эксклюзивного доступа**: нельзя пересекающиеся обращения к одной области памяти, если хотя бы одно из них — **запись**. Касается `inout`, `mutating`, элементов коллекций, subscript. Это про один контекст, **не** про потоки.

<details><summary>🔍 Детали: почему · ловушка · 🧠 якорь · вслух</summary>

🔑 **Почему.** Гарантия «мутация = эксклюзивная транзакция» даёт компилятору право оптимизировать (reordering/inlining) без изменения наблюдаемого поведения.

⚠️ **Ловушка.** Это **не** thread-safety: data race между потоками остаётся (нужны actors/синхронизация). Часть случаев ловится в рантайме (trap), а не на компиляции.

🧠 **Якорь.** Пока кто-то переодевается (write) — примерочная занята, никто не входит. Но это правило одной примерочной, не охрана всего магазина (потоки — отдельно).

💬 **Вслух.** «Закон эксклюзивности запрещает перекрывающиеся доступы, если хоть один — запись. Это про корректность в одном контексте, не про межпоточную безопасность.»

⚡ **А если спросят:** «`swap(&x, &x)` — что будет?» → Ошибка overlapping access (ловится компилятором).

</details>

<details><summary>📖 Глубже + код</summary>

```swift
func swapInts(_ a: inout Int, _ b: inout Int) { let t = a; a = b; b = t }
var x = 1
// swapInts(&x, &x)   // ❌ overlapping access — компилятор не разрешит

struct S {
    var arr = [1, 2, 3]
    subscript(i: Int) -> Int { get { arr[i] } set { arr[i] = newValue } }
}
func g(_ x: inout Int, _ y: inout Int) { x += 1; y += 1 }
var s = S()
// g(&s[0], &s[1])     // ❌ часто запрещено: overlapping через subscript
```

*Источники:* Swift Evolution — Law of Exclusivity; WWDC по memory safety.

</details>

## Q11 · TEXT и DATA сегменты памяти &nbsp;🔴
📋 *Перечисли сегменты памяти (TEXT/DATA/BSS…) и их права доступа.*

🎯 **Ядро.** Секции образа процесса (Mach-O). **TEXT** (`__TEXT`) — код + read-only константы, **RX** (read+execute). **DATA** (`__DATA`) — инициализированные глобальные/статические, **RW**. **BSS** — неинициализированные (обнуляются при старте). Рядом: **Heap** и **Stack**.

<details><summary>🔍 Детали: почему · 🧠 якорь · вслух</summary>

🔑 **Почему разделено.** Безопасность: **W^X** — страница либо пишется, либо исполняется, но не одновременно (+ ASLR, code signing) → код нельзя подменить в рантайме.

🧠 **Якорь.** TEXT — печатная книга: читай/исполняй, но не пиши в неё (RX). DATA — рабочая тетрадь: пиши и читай (RW). BSS — чистые, заранее обнулённые страницы.

💬 **Вслух.** «TEXT — код и константы (read+execute), DATA — инициализированные глобальные (read+write), BSS — неинициализированные (обнуляются). Разделение + W^X — про безопасность.»

⚡ **А если спросят:** «Глобальная `var g: Int` без значения — какой сегмент?» → BSS (память выделяется и обнуляется при старте).

</details>

<details><summary>📖 Глубже + код</summary>

- **Stack:** локальные переменные, кадры вызовов; быстро, LIFO, ограничен по размеру.
- **Heap:** динамические аллокации (объекты классов, буферы коллекций, ARC-managed); гибко, но дороже.

```swift
var g1 = 10                       // глобальная инициализированная → DATA
var g2: Int                       // глобальная без init → BSS
struct S { static var x = 1 }     // статическая → DATA/BSS
func f() {
    let a = 1                     // часто stack / регистры
    let obj = NSObject()          // объект → heap, указатель может лежать на stack
}
```

Точный набор секций (`__DATA_CONST`, `__LINKEDIT`…) зависит от toolchain — важен смысл RX vs RW.

*Источники:* Mach-O format, dyld, iOS memory protection (W^X, ASLR).

</details>

## Q12 · Проектирование value-типов без лишних копий и ARC &nbsp;🔴
📋 *Как проектировать value-типы без лишних копий и retain/release? Перечисли приёмы.*

🎯 **Ядро.** Держать value-типы **маленькими и плоскими**, опираться на CoW стандартных типов и не ломать его, минимизировать reference-поля, мутировать пачкой (`inout`/batching) — чтобы сохранить value semantics без лишних копий и retain/release.

<details><summary>🔍 Детали: почему · ловушка · 🧠 якорь · вслух</summary>

🔑 **Почему.** Каждая копия struct = retain/release всех её class-полей + возможная уникализация буфера; в горячем цикле это бьёт по скорости.

⚠️ **Ловушка.** `Data ↔ [UInt8]` и slices молча копируют; цепочки `.map().filter().sorted()` плодят промежуточные буферы.

🧠 **Якорь.** Лёгкий рюкзак копировать дёшево; набил классами-гирями и копируешь в цикле — каждый раз платишь за ARC и буфер.

💬 **Вслух.** «Держу типы лёгкими, не провоцирую уникализацию в циклах, мутирую через inout/batching, минимизирую class-поля. Большое значение — оборачиваю в кастомный CoW. Проверяю Allocations.»

⚡ **А если спросят:** «`.map().filter().sorted()` на большом массиве — в чём риск?» → Промежуточные аллокации; лучше один проход или `lazy`.

</details>

<details><summary>📖 Глубже + код</summary>

```swift
func process(_ input: [Int]) -> [Int] {     // batching: одна логическая копия
    var out = input
    out.reserveCapacity(out.count)
    for i in out.indices { out[i] *= 2 }     // in-place, без промежуточных массивов
    return out
}

func normalize(_ data: inout [Int]) {        // мутация in-place через inout
    for i in data.indices { data[i] = max(0, data[i]) }
}

data.withUnsafeBytes { raw in /* чтение без копии */ }
```

CoW-обёртка (`class Storage` + `isKnownUniquelyReferenced`) даёт value semantics с контролируемой стоимостью, но требует дисциплины (и не решает thread-safety).

*Источники:* Swift stdlib (Array/Data/String), `isKnownUniquelyReferenced`, Instruments.

</details>
